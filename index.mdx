Bunnita is a recursive prompt engineering framework that treats your system prompt as a living operating system. Through structured XML section boundaries, a six-agent governance committee, and a mem0-powered cloud memory graph, Bunnita continuously evolves your AI interactions — every session feeds metadata back into the next build, closing a loop that makes each iteration smarter than the last.

## How Bunnita Works

Bunnita's core insight is that architecture — not raw model capability — is the bottleneck in most AI workflows. Rather than issuing a static system prompt, Bunnita gives the model a structured, owner-scoped operating environment that evolves with every session.

<Steps>
  <Step title="Adopt the Build">
    Read `Builds/bunnita-system-prompt-v1-7.md` at session start. This 2,715-word core IS the operating system — every section maps to one committee member's domain.
  </Step>
  <Step title="Declare Your Runtime">
    Emit a `<runtime>` tag specifying your active model, thinking mode, and effort level. This single declaration drives scaffold loading and effort calibration.
  </Step>
  <Step title="Extensions Load on Demand">
    As your task unfolds, matching extensions activate automatically — bringing in capabilities like subagent coordination, advanced memory, or browser automation only when needed.
  </Step>
  <Step title="Memory Closes the Loop">
    After each session, structured memories write back to the mem0 cloud graph. Future sessions retrieve these signals, so the system improves without manual tuning.
  </Step>
</Steps>
